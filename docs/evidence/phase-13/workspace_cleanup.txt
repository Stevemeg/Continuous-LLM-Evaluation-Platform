Every file left behind is a git packfile, and every one carries the read-only
attribute. Nothing else survived. This is the diagnosis: shutil.rmtree raises
PermissionError on a read-only file on Windows, ignore_errors=True discards the
exception, and the packfiles remain. It is NOT open file handles, which is what
the leak had previously been attributed to.

The only line that differs between the two runs is W-6's reclaimable count,
952 -> 0, which is the reclamation being visible from inside the proof.

W-1 is a control, not a check of the fix: it runs the ORIGINAL code against the
original input and requires it to fail, so that the fix below it is answering a
demonstrated failure rather than a plausible story about one. It reports PASS
when the defect reproduces.

W-3 and W-4 are the two halves of "robust when Windows file handles are still
open". W-3 shows a handle released during the backoff window is ridden out --
0.70s of retrying, then success. W-4 shows a handle never released produces a
raised OSError naming the path. Silence is the one outcome neither permits, and
silence was the original defect.
